Setting it up

Everything wrapped.gg needs is a folder your server already writes. You need a Discord account and your host's file manager - no commands, no config files, nothing to restart. About five minutes.

1

Start on the panel

Sign in with Discord, type your server's name, add your icon. Open the panel

2

Zip the stats folder

In your host's file manager open world, tick the stats folder, and press Archive (or Compress). Download the file it makes - about 8 MB.

On Minecraft 26.X and newer that folder moved: it is world/players/stats. On anything older it is still world/stats. Either one works here.

3

Drop it in

Drag that file onto the setup page. Add usercache.json from your server's main folder too, so players have names.

4

Publish and post the link

Press Publish, paste your link in your Discord, and everyone looks themselves up.

That is the whole thing. Everything below is only if you get stuck.

The two files, and where they live
plugins/ world/ ← your main world playerdata/ region/ stats/ ← this folder. zip it. server.properties usercache.json ← this file. out here, not in world/ server.jar
usercache.json is what turns UUIDs into names. Without it every player is a row of letters and numbers and nobody can find their own page.
Minecraft 26.X moved the stats folder

From Minecraft 26.X onwards, per-player files live under a players folder, so the path is world/players/stats:

world/ players/ stats/ ← 26.X and newer advancements/ region/ world/stats/ ← 25.X and older. still the path on most servers today.

You do not have to know which one you have: zip whichever stats folder your file manager shows you, or drop the whole world folder in and we will find it. The shell command and the hosting-provider API both check the new path first and fall back to the old one.

Put it on your website

If you already have a site, you do not have to send people away from it. Paste two lines and the same Wrapped runs inside your page: the same search box, the same cards, the same share image. Nothing is different except the border around it.

<div data-wrapped="your-slug"></div> <script src="https://wrapped.gg/embed.js" async></script>

Your slug is the last part of your link - wrapped.gg/your-slug. The panel has the snippet with yours already filled in, next to a live preview of the result. The <div> goes where you want the box; the script can go anywhere on the page, and one copy covers as many boxes as you like.

Once it is in, it takes care of itself:

  • The box sizes itself to the search panel, and to the width you give it.
  • When somebody opens their year it goes full screen over your page, because a story in a 600px box is not worth reading. Closing it puts them back on your page where they were - so does the browser's back button.
  • The card still downloads, and still copies straight into Discord.
AttributeWhat it does
data-wrappedYour slug. The only one you need.
data-playerSkip the search box and open one player's year - data-player="Notch". Good on a staff page.
data-heightA fixed height in pixels. Leave it out and the box picks its own.
data-expand="off"Keep everything inside the box instead of going full screen. Give it at least 600px of height if you do.
No script? Then just an iframe

Site builders that strip <script> tags usually still allow an embed block. This works on its own - it only misses the automatic sizing and the full-screen step:

<iframe src="https://wrapped.gg/embed/your-slug" style="width:100%;height:700px;border:0" title="Wrapped" loading="lazy" allow="clipboard-write"></iframe>

Keep allow="clipboard-write" - without it the "copy image" button on the share card cannot reach the clipboard.

Where does this work? Wix, Squarespace, Carrd, WordPress…

Anywhere you can paste HTML. Look for a block called Embed, Custom HTML, Code or HTML widget and put the snippet in it. On WordPress it is the Custom HTML block, not the paragraph one. On Carrd it is Embed with the mode set to Code.

If your builder blocks scripts, use the iframe version above. If it blocks iframes too - some free tiers do - link to your page instead; nothing else will get through.

The box says "nothing here yet"

Either the slug is wrong or the page is not published. Copy the last part of your own link from the panel - it ends in a short random code, and that code is part of the slug.

Does it slow my site down?

The script is about 4 KB, and about 1.5 KB over the wire once it is compressed. A box below the fold does not load until somebody scrolls to it. Nothing runs on your page except sizing the frame; everything else happens on our side.

We set no cookies from the embed. Views through it are counted the same way as views on your Wrapped page, and your panel shows them separately so you can see whether it is earning its space.

If you get stuck

Where is the file manager on my host?
  • Pterodactyl (DedicatedMC, Bloom, Sparked, PebbleHost, most game hosts) - the Files tab on the left. Open world, tick stats, press Archive at the bottom, then download the .tar.gz it creates.
  • Multicraft (Apex, ShockByte) - Files → FTP File Access, same path.
  • Aternos, Minehut, free hosts - Files. If there is no archive button, download the whole world instead; we only read the stats out of it.
  • Your own VPS - skip all of it, see the command below.
  • Realms - not possible. Realms gives nobody access to the files.
I don't have a "world" folder

It has been renamed. Open server.properties and find the line starting level-name= - whatever follows it is your world folder. The _nether and _the_end folders never contain stats; only the main one does.

It says there are no player stats in my file

Almost always the wrong folder got zipped. Go back to world, tick the stats folder itself rather than opening it first, and archive that.

If there is no stats folder directly inside world, you are on Minecraft 26.X or newer - look in world/players/stats instead.

A zip of the whole world works too, or even the whole server - we ignore everything except the stats. What does not work is the advancements folder, which looks similar and is not it.

My host has no archive or compress button

Download the whole world as a zip if your host offers that, and drop it in as-is. Otherwise connect with FileZilla, drag the stats folder to your desktop, and zip it there - right-click → Compress on a Mac, or Send to → Compressed (zipped) folder on Windows.

Everyone shows up as letters and numbers

usercache.json was missing. It sits in your server's main folder next to server.properties, not inside world/. Upload again with it attached - the rebuild replaces the old one and there is nothing to clean up.

My server runs an old version of Minecraft

That is fine. Minecraft changed the shape of a stats file in 1.13, and again further back in 1.8, and all three shapes are read here. A 1.7.10 file records blocks by number rather than by name; those numbers are translated back into blocks, so the awards, the leaderboards and the totals come out the same as they do for a server on the latest release.

Two things genuinely are not in an old file, and nothing can invent them: statistics Minecraft had not added yet - elytra distance before 1.9, anything about raids - and, on 1.7.5 and older, the account UUID. Those versions named each file after the player instead, and every page here is keyed on the UUID, so those files are skipped unless usercache.json can match them. From 1.7.6 onwards Minecraft renamed the files itself and there is nothing to do.

A player types their name and nothing is found
  • They changed their name since your upload. Upload again.
  • They play on Bedrock. Geyser adds a prefix, usually a dot. Searching works with or without it, so try the bare name first.
  • They never played on the world you uploaded.

If lots of searches fail, the Traffic section of your panel says so.

I have SSH - is there a faster way?

Yes. From your server's folder, the one with server.properties in it:

curl -sL https://wrapped.gg/u | sh -s -- --key wgg_live_yourkey

It finds the world itself, needs only curl and python3, and never touches the running server - safe with players online. The panel offers this during setup with your key already filled in.

Can I upload again later?

As often as you like, up to twelve times a day. Each upload rebuilds the page in place. Your link never changes and links your players have already shared keep working.

For a page describing just this year rather than all time, upload twice - once now, once in December - then set the first as the baseline under Time window. Minecraft's counters never reset, so that subtraction is the only way to get a real window.

Does this affect my server at all?

No. Nothing is installed, nothing runs alongside the game, there is no plugin or mod to keep in step with Minecraft versions. You are copying files your server already wrote, and you do not need to stop it to do so.

We read the stat counters and the name that goes with each UUID. We never see chat, commands, logs, IPs, coordinates, builds or inventories.

Why are there no advancements?

They are 98% recipe-unlock noise - on our reference server, 6,003,511 entries of which 112,278 were real - in a 948 MB folder. Counters tell a much better story for a fraction of the effort.

I run a hosting company and want this in my panel

There is an API for exactly that. One call creates a customer's Wrapped and hands you an upload key; a scheduled task on the server sends the stats. Your customers press a button in your panel and never see a key or a setup guide.
